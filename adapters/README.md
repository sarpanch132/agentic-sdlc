## Invocation and capability semantics verified for fixround1

- [Claude skill invocation](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill): user-only metadata blocks model Skill calls. Callable helpers use false instead; scope is their active-workflow description/body.
- [Claude subagent tools](https://code.claude.com/docs/en/sub-agents#restrict-which-tools-a-subagent-can-use): a tools allowlist removes unlisted tools/MCP. Omission preserves the host-provided pool, subject to host version, permissions, foreground/background and nesting limits. Coordinator/researcher omit it; review allowlists remain intentional. A subagent may still lack orchestration due to host limits: disclose and return that work to the main session.
- [Cursor skills](https://cursor.com/docs/skills): true means explicit slash invocation only; defaults allow relevance-based use. Callable helpers use false. Cursor recursively discovers SKILL.md, so canonical workflow is installed as WORKFLOW.md.
- [Codex skills](https://learn.chatgpt.com/docs/build-skills): allow_implicit_invocation defaults true; false prevents implicit prompt-based invocation while explicit invocation still works. Core uses false; helpers explicitly use true with the same active-workflow guard.

These primary docs were checked 2026-10-28; they do not prove identical behavior in installed client versions. `evidence/helper-invocation-cases.json` adds three required acceptance transitions from an explicitly invoked core to brainstorming, UIUX and Graphify without separate helper invocation, including unrelated-request rejection. Static assertions pass; real host executions remain NOT RUN and cannot be called behavioral passes. No model calls, settings writes or new permissions were used.
