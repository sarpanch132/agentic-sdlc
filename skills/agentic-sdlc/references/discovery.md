# Adaptive discovery

Reflect confirmed understanding briefly, identify the most consequential missing essential fact, then ask one focused question. Do not present this reference as a mandatory questionnaire. Reuse facts already provided in the conversation and applicable project context; ask to resolve contradictions rather than silently selecting one.

Consider only relevant gaps:
- Goal: problem, desired outcome and why it matters.
- Audience: intended users, context and principal journeys.
- Success: observable acceptance criteria.
- Alternatives: known competitors, current workarounds and desired differentiation.
- Non-negotiables: requirements that cannot be compromised.
- Scope: first-version boundaries and exclusions.
- UI/UX when relevant: look, feel, branding, interactions, accessibility and devices.
- Prototype: whether a small proof would resolve an important uncertainty; proposing one does not authorize building it.
- References: request screenshots, sketches, images or examples when they would clarify essential visual/interaction intent. Never invent absent image contents.
- Constraints: budget, timeline, technology preferences, compatibility, privacy and business rules.
- Authority: intended workspace and actions beyond established permission.

Explain unfamiliar choices plainly and offer a recommendation with its tradeoff. A recommendation is not a requirement until agreed. Mark irrelevant topics not applicable with a reason. Record undecided items explicitly; defer nonessential decisions with a reason and a revisit gate. Essential unknowns block dependent design/build work, not independent authorized inspection.

Inspect technical capabilities independently within access: source structure, stack, tests, documentation, relevant project-local graph, available agents/skills/MCP metadata and permission boundaries. Ask only when user intent or authority cannot be established from supplied facts. With no meaningful code corpus, skip Graphify extraction. With relevant graph context, query it before broad source searches; extract local code-only when cross-file exploration warrants it, verify source before edits and refresh stale affected context. Never upload documents automatically.

Produce a short brief separating confirmed requirements, unresolved questions, deferred decisions, scope/exclusions, constraints, acceptance criteria and authority. Ask the user to confirm it before design/build gates. A complete backend bug report may need only this confirmation; do not add competitors, prototype or visual questions that cannot affect that fix.
